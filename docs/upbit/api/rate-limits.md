# 업비트 요청 수 제한

출처: https://docs.upbit.com/kr/reference/rate-limits  
정리일: 2026-05-29

## 기본 정책

- 요청 수 제한은 초 단위로 적용된다.
- API가 속한 Rate Limit 그룹별로 초당 최대 요청 수가 정해진다.
- 같은 그룹의 API는 요청 수가 함께 집계된다.
- 서비스 상황에 따라 추가 제한이 적용될 수 있고, 그룹별 정책은 공지 후 변경될 수 있다.
- `Origin` 헤더가 포함된 시세 REST API 및 WebSocket 요청은 별도 정책으로 10초당 1회만 허용된다.

## 제한 단위

| 기능 | 제한 단위 | 설명 |
| --- | --- | --- |
| Quotation REST API | IP 단위 | 같은 IP의 요청이 함께 집계된다. |
| Exchange REST API | 계정 단위 | 같은 계정에서 발급한 여러 API Key 요청이 함께 집계된다. |
| WebSocket | 인증 포함 시 계정 단위, 인증 미포함 시 IP 단위 | 시세 구독은 보통 IP 단위, 내 주문/자산 구독은 계정 단위다. |

## Rate Limit 그룹

### Quotation REST API

| 그룹 | 제한 | 대상 |
| --- | --- | --- |
| `market` | 초당 최대 10회 | 페어 목록 조회 |
| `candle` | 초당 최대 10회 | 초/분/일/주/월/년 캔들 조회 |
| `trade` | 초당 최대 10회 | 페어 체결 이력 조회 |
| `ticker` | 초당 최대 10회 | 페어 현재가, 마켓 현재가 조회 |
| `orderbook` | 초당 최대 10회 | 호가 정보 조회 |

### Exchange REST API

| 그룹 | 제한 | 대상 |
| --- | --- | --- |
| `default` | 초당 최대 30회 | 잔고, 주문 조회/취소, 입출금 조회/요청, 트래블룰, 서비스 상태, API Key 목록 등 |
| `order` | 초당 최대 8회 | 주문 생성, 취소 후 재주문 |
| `order-test` | 초당 최대 8회 | 주문 생성 테스트 |
| `order-cancel-all` | 2초당 최대 1회 | 주문 일괄 취소 |

### WebSocket

| 그룹 | 제한 | 대상 |
| --- | --- | --- |
| `websocket-connect` | 초당 최대 5회 | WebSocket 연결 요청 |
| `websocket-message` | 초당 최대 5회, 분당 100회 | WebSocket 데이터 요청 메시지 전송 |

## 잔여 요청 수 확인

REST API 응답의 `Remaining-Req` 헤더로 잔여 요청 수를 확인한다.

```http
Remaining-Req: group=default; min=1800; sec=29
```

| 필드 | 의미 |
| --- | --- |
| `group` | 요청이 포함된 Rate Limit 그룹 |
| `min` | 현재는 deprecated 된 분 단위 제한 정보. 고정값이므로 참조하지 않는다. |
| `sec` | 현재 초 단위 잔여 요청 수 |

`sec=0`이면 잔여 요청 수가 없는 상태이므로 일정 시간 이후 재시도해야 한다.

## 초과 시 응답

- 제한 초과 시 `429 Too Many Requests`가 반환된다.
- 429 이후에도 계속 요청하면 IP 또는 계정 단위로 일시 차단될 수 있다.
- 차단 시 `418` 상태 코드와 차단 시간이 반환된다.
- 정책 위반이 반복되면 차단 시간이 점진적으로 증가할 수 있다.

## 구현 체크리스트

- 요청 전 API별 Rate Limit 그룹을 확인한다.
- REST 응답의 `Remaining-Req` 헤더를 파싱해 내부 요청 가능 횟수를 갱신한다.
- `sec`가 낮거나 0이면 요청을 지연한다.
- 429 발생 시 즉시 재시도하지 말고 백오프한다.
- 418 발생 시 응답의 차단 시간 이후에만 재시도한다.
- WebSocket은 연결 요청과 구독 메시지 요청 제한을 별도로 관리한다.
