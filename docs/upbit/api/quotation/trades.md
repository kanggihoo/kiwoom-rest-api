# Quotation API - 페어 체결 이력 조회

출처: https://docs.upbit.com/kr/reference/list-pair-trades  
정리일: 2026-05-29

## 핵심 요약

지정한 페어의 최근 체결 이력을 조회한다. 과거 체결을 페이지처럼 이어 조회하기 위해 `cursor`, `to`, `days_ago` 파라미터를 사용할 수 있다.

## Endpoint

```http
GET https://api.upbit.com/v1/trades/ticks
```

## Rate Limit

| 항목 | 내용 |
| --- | --- |
| 그룹 | `trade` |
| 제한 | 초당 최대 10회 |
| 측정 단위 | IP 단위 |
| 공유 범위 | 체결 그룹 내 요청 가능 횟수 공유 |

## Query Parameters

| 파라미터 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `market` | string | 필수 | 조회할 페어 코드. 예: `KRW-BTC` |
| `to` | string | 선택 | 조회 기준 시각 |
| `count` | integer | 선택 | 조회 개수. 기본값 `1` |
| `cursor` | string | 선택 | 연속 조회를 위한 커서 |
| `days_ago` | integer | 선택 | 조회 일자 범위 지정용 파라미터 |

## 변경 이력 메모

- 2020-07-17: 조회 기간 7일로 확대 지원

## 응답 개념

응답은 체결 목록이다. 일반적으로 다음 성격의 값을 사용한다.

- 체결 시각
- 체결 가격
- 체결량
- 매수/매도 방향
- 체결 식별용 순번 또는 타임스탬프

## 구현 체크리스트

- 실시간 체결 수신은 WebSocket `trade` 구독을 우선 검토한다.
- REST 체결 이력은 초기 로딩, 재동기화, 누락 구간 보정에 적합하다.
- 과거 데이터를 이어 받을 때는 `cursor` 기반 페이지 처리를 고려한다.
- 요청 기간과 `count` 조건에 따라 원하는 수보다 적게 반환될 수 있으므로 빈 배열과 부분 응답을 정상 케이스로 처리한다.
