# 업비트 API 개요

출처: https://docs.upbit.com/kr/reference/api-overview  
정리일: 2026-05-29

## 핵심 요약

업비트 API는 정보 성격에 따라 크게 두 영역으로 나뉜다.

| 구분 | 용도 | 인증 |
| --- | --- | --- |
| Quotation | 페어, 캔들, 체결 이력, 현재가, 호가 등 시세 조회 | 인증 없이 사용 가능 |
| Exchange | 계정 자산, 주문, 입출금 등 거래 및 자산 관리 | API Key 기반 인증 필수 |

## 연동 방식

| 방식 | 적합한 용도 | 특징 |
| --- | --- | --- |
| REST API | 주문 생성/취소, 입출금 요청, 낮은 빈도의 조회 | 요청-응답 방식이라 구현과 테스트가 단순함 |
| WebSocket | 실시간 시세, 체결, 호가, 내 주문/자산 이벤트 구독 | 연결 유지, ping/pong, 재연결 처리가 필요함 |

## 기능 분류

### Quotation

- 페어: 업비트가 지원하는 전체 페어 목록 조회
- 캔들: 초/분/일/주/월/년 단위 OHLCV 조회
- 체결: 페어별 최근 체결 이력 조회 및 실시간 체결 구독
- 현재가: 페어 또는 마켓 단위 현재가 조회 및 실시간 현재가 구독
- 호가: 호가 정보 조회 및 실시간 호가 구독

### Exchange

- 자산: 계정 잔고 조회, WebSocket 내 자산 변동 구독
- 주문: 주문 생성, 테스트 주문, 취소, 취소 후 재주문, 주문 조회
- 출금: 디지털 자산/원화 출금, 출금 취소, 출금 가능 정보 및 목록 조회
- 입금: 입금 주소 생성/조회, 입금 가능 통화 조회, 입금 목록 조회, 트래블룰 검증
- 서비스: 통화별 입출금 서비스 상태, API Key 목록 조회

## 구현 시 선택 기준

- 조회만 필요한 공개 시세 데이터는 Quotation REST API부터 검토한다.
- 주문, 잔고, 입출금처럼 계정 권한이 필요한 기능은 Exchange API이며 인증 구현이 선행되어야 한다.
- 실시간 자동매매나 모니터링처럼 지연 시간이 중요한 경우 WebSocket 구독을 사용한다.
- 주문 실행, 취소, 입출금 요청은 REST API 사용이 적합하다.
