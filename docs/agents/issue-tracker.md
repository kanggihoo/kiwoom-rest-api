# Issue Tracker

This repo does not use an agent-managed issue tracker.

## Policy

- Do not create GitHub Issues.
- Do not create GitLab Issues.
- Do not create local markdown issue files under `.scratch/`.
- Do not introduce issue labels or issue state workflows.

When a skill says "publish to the issue tracker", stop and ask the user where they want that artifact written. Prefer an inline plan or a document under `docs/` when the user has not requested issue creation.

When a skill says "fetch the relevant ticket", ask the user for the source document or path. Do not infer an issue tracker.
